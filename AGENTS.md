# Veyra website publication

The user wants verified website changes in this project published automatically
to the Cloudflare Workers project `veyra-website` in the `Veyra Browser` account.

- Edit `website/` and `worker/`; `dist/` is generated by the site build.
- After completing and checking changes to the website, Worker, download links,
  or release metadata, run `npm run site:deploy` before finishing the task.
  This command runs the Worker tests, builds the website with metadata from the
  verified Windows GitHub Release, and deploys to workers.dev. Website changes
  never re-upload the ZIP. The user explicitly prefers hosting without R2.
- Publish once after the complete change has passed its checks. Do not deploy
  intermediate files while a task is still in progress.
- Follow an explicit user request to keep a particular task local or unpublished.
- Use `cloudflare/wrangler.json` for direct Cloudflare publication. Preserve
  `.openai/hosting.json`, which belongs to the separate existing Sites setup.
- Use the existing Cloudflare login or environment credentials. Never commit,
  print, or paste API tokens or passwords. If authentication/deployment fails,
  preserve the local result and report the actual blocker; do not claim it is live.
- Keep the complete portable ZIP available locally. Workers static assets exclude
  ZIP files via `website/.assetsignore`; the Worker redirects downloads to the
  matching public GitHub Release. Do not enable R2 or paid storage for this setup.
- New Windows releases are built and tested on GitHub by `.github/workflows/build.yml`,
  including a `publish-download` job. If the app version changes, push its source
  and wait for that workflow to publish the matching release before deploying
  the website. Use the existing GitHub login; do not upload large local ZIPs
  from this machine unless the user explicitly requests that route.
- On workers.dev, `/analytics` and its summary API require the optional
  `ANALYTICS_PASSWORD` secret (Basic username `veyra`). Without this secret they
  remain disabled. Do not expose the dashboard publicly.
